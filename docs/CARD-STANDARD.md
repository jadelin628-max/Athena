# 卡片粒度与体量标准

> 立此文的原因：2026-10-11 用户反馈「第一波新加的卡片充满了大量内容…不符合我的要求，也没有对已有的繁琐卡片进行拆分」。
> 本文把「卡片该多大、什么时候必须拆」写成**可度量、可复算、可验收**的规则，供后续所有补写/重写/拆分切片遵循。
> 适用范围：`data/*.js` 的 `DATA`（知识卡）。技能科 / 语言科同规则。

## 1 四条硬标准

1. **一卡一知识点**
   - `title` 就是这张卡唯一要讲的知识点；`back` 只讲这一件事。
   - 出现「（1）（2）」「①②③」等**互不依赖**的并列结论，或「一个概念 + 一个独立方法/性质」混装，即须拆分。
   - 不算多知识点的情形：同一知识点的「定义 → 判据 → 常见陷阱」多侧面展开。
   - 有先例可循：数三曾做过一卡一知识点拆分（29 张重灾区，328→397 卡；原 id 承接核心点，新增 `kn01–kn72`，解题套路卡只留步骤、知识点另立并 `REL` 关联）。

2. **正文体量：净字数 ≤ 300，硬上限 400；> 400 一律拆分。**

3. **正文纯净**（既有闸门在管，此处重申）
   - 正文不得出现 PDF / 教材 / 讲义 / 专题的引用或页码；正文不得泄漏内部卡片 id。
   - 例题、陷阱、提示分别放 `EXAMPLE` / `PITFALL` / `MNEM`，**不计入正文字数**。

4. **题面与正文必须阐释知识点，不得照抄例题或具体题目**
   - `front` 不得照抄本卡或别卡 `EXAMPLE.q` 的题干，`back` 不得照抄本卡 `EXAMPLE.a` / `a2` 的解答。
   - 例题的数字设定（$Q=100$、$q=2/3$、$F=1200/7$、$p=100/3$ 之类）不得写进正文；正文用符号参数（$q_H,q_L,\beta,\lambda,L,v,c$）讲一般规律。
   - `front` 不得是题目式题面（`求导数：…` / `求不定积分：…` / `求极限：…` / 「设…，求…／证明…」），应为知识点命名或知识点问句；方法卡用「给定…如何求…／…的通用套路」表述，不算题目式。
   - 守卫：`tests/card-content.test.mjs`（含在 `npm test` 内）——6-gram 对称 Jaccard 门槛 S1(front↔本卡例题题干) ≥ 0.45、S2(back↔本卡例题解答) ≥ 0.55、S3(front↔同科别卡例题题干) ≥ 0.45，配 `front ≥ 24 / back ≥ 48 / 例题侧 ≥ 24`、shingle ≥ 8 的长度门槛；另查三科考试学科的题目式前缀。

## 2 度量口径（可执行定义）

- **正文** = `DATA[i].front` + `DATA[i].back`（不含 `META`/`EXAMPLE`/`PITFALL`/`MNEM`/`REL`）。
- **净字数 net** = 正文去掉 LaTeX 命令名（`\cmd`）、结构符与定界符（`{ } $ ^ _ & ~`）以及全部空白后的字符数。
  公式里的字母、数字、运算符仍计入 —— 数学卡不会因为公式写法规范而被误判。
- **原文字符 raw**（含 LaTeX 与标点，空白折叠为 1）只作「屏幕上占位」的参考值，**不作判据**。
- **量具**：`backup/scratch/captain-recon-b/recon22.mjs`
  → 输出 `backup/scratch/captain-recon-b/recon22.txt`（含分档、超限名单、第一波新卡体量）与 `bwave-plan.json`（机读）。
  改完卡片重跑一次即可复算达标情况。

## 3 拆分规则

- **id**：原 id 留给承接核心知识点的那张；新增子卡用 `<原id>-2`、`<原id>-3`…（例：`pb14` → `pb14` + `pb14-2`）。
- **REL**：父卡与子卡之间保留 `REL` 关联，保证从任一子卡能走到其余子卡。
- **字段归位**：`META`（星级）、`PITFALL`、`MNEM`、`EXAMPLE` 必须重新归位到真正对应的那张卡；不得留下指向已迁走内容的字段。
- **例题**：不得因拆分而复制或编造例题。一道真题可跨知识点复用，但每张卡的例题 `src` 必须仍是原例题的原始来源串。
- **进度**：拆分不重置已学卡片；但**新增 id 的学习记录从零开始**（与原「整科重置」口径不同 —— 只有被拆的那张卡受影响）。
- **计数**：拆分必然改变卡片数与「一卡一例题」覆盖率统计，**必须同批更新** `docs/COVERAGE.md` 与 `docs/BOARD.md` 的计数终值。

## 4 拆分后必跑（一个切片一个交付）

1. 改了 `EXAMPLE` ⇒ 必须重生成题库派生块：
   `node tools/bank-cv.mjs --subject <sid> --write --allow-workspace-write`（math3 另加 `--allow-math3-reorder`）。
2. `node tools/check_data.mjs`、`node --test tests/bank.test.mjs`（`T49_CARDS` 的 `kept`/`poc` 期望值需同步现算）。
3. 总闸：`npm test`、`npm run check`、`npm run check:render`。
4. 重跑 `recon22.mjs` 复算体量分布 —— **达标才允许收口**。
5. 结论写入 `docs/BOARD.md` 对应任务块（不写实现过程）。
