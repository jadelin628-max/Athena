# WORKFLOW — Vibe Coding 实操约定

> 目标：短上下文、低幻觉、可验收、可续作。与 `AGENTS.md` 硬禁区叠加生效。

## 1. 会话切片：一次只做一件事

**好的切片**（可在单次会话内改完 + 跑完闸门）：

- 修一个已复现的 bug（附现象与根因假设）
- 给某一科补一批卡（给定章节与数量）
- 加一个有验收标准的小功能（如「错题列表加按来源筛选」）
- 写/改一份文档并对照代码核实

**坏切片**（必须先拆）：

- 「重构整个前端」「把所有科都教材化」「全面优化性能」
- 无验收标准的「改进体验」
- 同时动调度算法 + UI + 数据扩容


## 2. 上下文预算

| 策略 | 做法 |
|---|---|
| 冷启动 | 只读 `AGENTS.md`；按「必读地图」点开 1 份深文档；再读目标文件切片 |
| 禁止整仓通读 | `data/*.js` 单文件可达 25 万字节，只用 grep/抽样，不整读 |
| 决策落盘 | 选型、schema、范围边界写进 Spec/文档；**不要**指望长对话被记住 |
| 会话老化 | 一个切片做完就收尾（勾任务、写结论）；新切片优先新会话 |
| 粘贴克制 | 大段日志/全文只留「命令 + 结论 + 失败关键行」；全文留在磁盘 |
| 生成物不进脑子 | 不要反复讨论 `app.js` diff 全文；看 `src/` 即可 |

**恢复协议**：若会话压缩后丢失约定，在继续前重读 `AGENTS.md` + `docs/WORKFLOW.md`。

## 3. 防幻觉清单（动手前自检）

1. **命令**：是否来自 `package.json` / `tools/README` / 本文？禁止发明 npm script。
2. **路径/文件**：是否在仓库中真实存在？新文件是否有必要（优先改现有文件）？
3. **字段/函数**：是否在 `DATA_SCHEMA` 或目标源码中出现？禁止臆造 DB 字段或 `window` API。
4. **算法**：FSRS 相关是否与 `fsrs-core.mjs` 注释一致？非官方是否标 ⚠️ 并请示？
5. **内容事实**：卡片/例题是否来自真实教材或真题？禁止编造真题。
6. **版本/数量**：卡数、版本号、文件列表是否用工具数过，而不是估计？

不确定 → 查文件 → 仍不确定 → **问用户**或标「未核实」。不要把猜测写成事实。

## 4. 实施循环

```
定位（grep/读切片） → 最小修改 → 生成物构建（如需要） → 闸门测试 → 报告结果
         ↑                                              │
         └──────────── 失败则先复现根因（最多盲改 2 次） ←┘
```

- **测试优先**：有廉价复现时，先写失败测试再修；bug 修复尽量补回归测试。纯配置/生成/一次性原型可跳过。
- **失败两次停手**：同一点连续两次修不对，停下来重新推导根因（读错误、diff、最近提交），禁止继续打补丁。
- **不扩散**：顺手重构、改无关命名、清理「看着别扭」的代码一律不做；记入 `notes.md` 或下次切片。
- **生成物**：改 `src/` 后 `npm run build`；改 `CHANGELOG` 数据后 `node tools/changelog.mjs`。

## 5. 闸门表（完成定义）

| 改动面 | 完成 = 至少 |
|---|---|
| `src/*.mjs` | `npm run build` + `npm test` |
| 渲染/卡面 | 另加 `npm run check:render` |
| `data/*.js` | `check_data` + `check_render` |
| 升版本 | 七处改齐 + `check_version` |
| 合并/发版前 | `npm run check` + `npm test` |

`check_render` 需本机 Chrome/Edge；跑不了要在结论里写明 **未跑**，不可假绿。

## 6. 版本与变更记录

- SemVer：`patch` 修复 / `minor` 功能 / `major` 破坏（含 schema 不兼容）。
- 达到「用户可见的行为变化或修复」才升版；纯文档/内部重构可不升。
- 升版顺序：改七处 → `check_version` → `src/app.mjs` 的 `CHANGELOG` 加条目 → `node tools/changelog.mjs` → 报备。
- **不**在无用户要求时 `git commit` / `push`。

## 7. 子代理与并行

- 可并行：互不重叠文件集的调研、文档起草、测试补充。
- **禁止并行写同一文件**（尤其 `data/*.js`、`src/app.mjs`）。
- 给子代理的提示词必须自带：工作区绝对路径、任务边界、验收标准、必读文档路径；**不要**传本会话闲聊史。
- 子代理结论是主张：抽样 diff/复跑廉价命令核实后再写入最终报告。
- 重测试/构建与代码审阅不要与同一环境上的重负载任务重叠。

## 8. 文档维护

- 代码事实变更后 **回写** 受影响文档（模块增删改 `ARCHITECTURE`；字段增删改 `DATA_SCHEMA`；流程变化改本文/`AGENTS.md`）。
- 文档冲突：以代码为准，并开一条小切片修文档。
- 不为临时讨论新建平行 md；长期结论进 `docs/`，自由备忘进 memory 的 `notes.md`。

## 9. 与用户协作

- 范围/验收/破坏性操作（删数据、改调度语义、升 major）→ 先问再做。
- 汇报格式：**改了什么 → 闸门结果（命令 + PASS/FAIL）→ 下一步**。不写冗长过程叙事。
- 实操建议类问题：给可执行条目，并尽量引用本仓库已有机制（闸门、生成物、Spec），不空谈方法论。
