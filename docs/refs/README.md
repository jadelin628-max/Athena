# 参考资料读图裁定（refs rulings）

> 本目录是 **2.2.0「内容全覆盖 + 题库全量」** 波次的参考资料转录基线工作台。
> 目的：让每一份参考资料（PDF 扫描件、无文本层或 OCR 碎裂页）都能被**逐页定位、逐条取证、可复现复核**，
> 而不是靠记忆、推测或不可靠的 OCR 文本。
>
> 本文件（`docs/refs/README.md`）只定义**工具用法 + 记录格式 + 通道口径**，本身不承载裁定内容；
> 各族的裁定记录写在 `docs/refs/rulings/<族>.md`，族级基线写在 `docs/refs/<族>*.md|.json`。

## 1. 通道口径（写死，不可协商）

| 通道 | 用途 | 状态 |
| --- | --- | --- |
| **自带 `read_image`**（主通道） | 把 PNG 裁片读进上下文、逐字抄录原文 | ✅ **唯一主通道** |
| **`modlens`**（含 `modlens_read_image`） | — | ⛔ **禁用** |
| OCR 文本（`参考文件/_extract/*.txt`） | 只用来**找页、找行、找线索** | ⚠️ 不得作为题面/公式依据 |
| 网络信源 | 只做**第三源交叉核对**，且需记录 URL 与本地留档路径 | ⚠️ 辅助 |

**为什么禁用 modlens**：它走**独立额度**。额度耗尽时它不会稳定报错，而是**返回退化/伪造的结果**，
把「额度耗尽」伪装成「读图失败」或更糟——伪装成「读图成功但内容错了」。
读图裁定的全部价值在于「原文可信」，因此不得使用任何会把失败伪装成成功的通道。

**主通道的代价与补偿**：`read_image` 会消耗主对话上下文，因此本流程要求**先裁小**（`--box`）再读，
一次只读一题/一段；裁片本身不进仓库，命令与 sha256 进裁定记录，可随时重建。

### 1.1 三源一致原则（入库/落基线的前提）

1. **题面/正文**：裁片图像逐字可读，**无不确定字符**；
2. **答案/结论**：在解析册、教材正文或其它来源页可定位（或由裁定者独立重推）；
3. **独立复核**：裁定者自己推一遍（选择题可穷举验证），结论与来源一致。

三源不齐 → **不入库/不落基线**，并在裁定文件里写明原因（`结论: 未裁定`）。

## 2. 工具：`tools/refs-vision.py`

把 PDF 某页（可裁剪）渲染成**确定性** PNG 裁片，并打印像素尺寸、字节数与 sha256。

### 2.1 依赖与解释器

- 纯标准库 + **PyMuPDF**；仓库内解释器 `参考文件/_venv/Scripts/python.exe` 已装 PyMuPDF（1.28.x）。
- `--python` 只影响回显的「等效命令」文本；工具本身由**当前解释器**运行。写法建议：

```powershell
& "参考文件\_venv\Scripts\python.exe" tools\refs-vision.py --pdf "<PDF>" --page <N> --dpi 150
```

### 2.2 参数

| 参数 | 必需 | 说明 |
| --- | --- | --- |
| `--pdf` | ✅ | PDF 路径。相对路径依次按 **当前目录 → 仓库根 → `参考文件/`** 解析 |
| `--page` | ✅ | 页码，**1 基**（PDF 第 1 页 = 1） |
| `--dpi` | — | 渲染分辨率，默认 `150` |
| `--box x0,y0,x1,y1` | — | 裁剪框，**PDF 点**为单位，**原点在页面左上角，y 轴向下**；省略＝整页 |
| `--out` | — | 输出 PNG 路径；省略时自动命名（见 §2.4） |
| `--python` | — | 写入「等效命令」的解释器路径，默认 `参考文件/_venv/Scripts/python.exe` |
| `--verify` | — | 只校验：重渲一次并与 `--out` 现有 PNG 比对 sha256，**不覆盖文件** |

退出码：`0` 成功｜`1` `--verify` 不一致｜`2` 参数错误｜`3` 文件/页码/依赖错误。

### 2.3 确定性（本工具的核心承诺）

- **同一 PDF + 同一 `--page`/`--dpi`/`--box` ⇒ 同一 sha256**，与运行次数、输出路径无关。
- 实现方式：`zoom = dpi/72`；`--box` 先按 `round(v*zoom)` 取整到**渲染像素网格**再换回 PDF 点交给
  `page.get_pixmap(matrix, colorspace=fitz.csRGB, alpha=False, clip=...)`；输出后直接读 PNG 的 IHDR 复核尺寸。
- 因此裁定记录里**必须**写下 sha256；事后用 `--verify` 复核：

```powershell
& "参考文件\_venv\Scripts\python.exe" tools\refs-vision.py --pdf "<PDF>" --page <N> --dpi 150 --box <box> --verify
# 一致 → exit 0（打印「结果: OK（一致）」）；不一致 → exit 1
```

### 2.4 裁片存放约定

**默认输出目录**（省略 `--out` 时自动生成）：

```
backup/scratch/refs-vision/<材料>/<PDF名>_p<页码>[_<x0_y0_x1_y1>]_<dpi>dpi.png
```

- `<材料>` 由 PDF 相对路径去扩展名后把 `/`、`\`、`、` 等替换为 `__` 得到（与 `参考文件/_extract/` 的命名同源，便于对照）。
- 例：`backup/scratch/refs-vision/真题__数学__5、【1987-2025年】考研数学三真题__2025年考研数学三真题/2025年考研数学三真题_p2_55_94_542_220_150dpi.png`
- **`backup/` 已被 `.gitignore:19` 整目录忽略**，裁片**不入库**；裁定记录里写「生成命令 + sha256」即可在任何时候重建。
- 允许 `--out` 写到任务自己的 scratch（如 `backup/scratch/refs-<族>/`）做过程图；但**裁定记录引用的正式裁片路径**
  一律用上面的默认目录形式，保证跨族可查。

### 2.5 坐标怎么定（`--box` 的正确用法）

1. 先整页跑一张：`--page N --dpi 150`（A4 页面 = 1241×1754 px）。
2. 目视估计目标区域在整页像素里的范围，换算 `点 = 像素 / (dpi/72)`；150 dpi 时 `点 = 像素 × 0.48`。
3. 裁片宁大勿小：**四边各留 5–10 点余量**，先确认「整块内容无截断」，再收紧。
4. 拿不准就逐条试探并记下每次的 `--box`（这些试探图也留在 scratch，不必写进裁定记录）。
5. 裁片尺寸 = `(x1-x0) × (y1-y0) × dpi/72` 四舍五入到整数像素；`rotation≠0` 的页面先按实际旋转核对。

### 2.6 裁片体积上限（**硬约束，船长 m03225 追加**）

- **单张 PNG ≤400 KB、最长边 ≤1400 px**。超限的裁片不要交给读图工具：图像通道会在取回时超时失败，报错形如
  `400 data: {"error":{"code":"invalid_parameter_error","message":"Download multimodal file timed out","type":"invalid_request_error"}} (code INVALID_REQUEST)`——
  这是平台侧取不回过大图像，**与任务理解无关**，重试同一张也不会成功。
- 首选做法：**先 `--box` 只裁目标版心块**（去掉页眉/页脚/相邻栏留白），必要时再降到 `--dpi 110`；仍超限则把一块拆成上下/左右两张分别亲读。
- 渲染命令会打印字节数与像素尺寸，**先看再递给读图工具**；超限就调参数重渲。
- 整页大图（如 150 dpi A4 ≈ 1241×1754 px）仅用于定位区域，不用于逐字转写。

## 3. 裁定记录格式（`docs/refs/rulings/<族>.md`）

### 3.1 硬性要求

每条裁定**必须**含以下字段；缺字段即视为无效裁定：

| 字段 | 要求 |
| --- | --- |
| **材料** | 仓库相对路径的 PDF（必要时加册内页脚/页眉说明，如「教辅扫描，页脚『第 N 页』」） |
| **页码** | **PDF 物理页码（1 基）**；若与印刷页码不同，两个都写 |
| **生成命令** | 可直接复制运行的完整体（含 `--box`） |
| **裁片路径** | 默认目录形式；补 `像素尺寸`、`字节数`、`sha256` |
| **亲读原文 ≥20 字** | **逐字抄录**；公式/符号写成 LaTeX（`$...$`）—— 这层 LaTeX 是**裁定者的转写层**，与纸质原稿的排版无关，但一旦定稿即视为「原文」的一部分，后续必须逐字沿用 |
| **结论** | 一句话判定：这条内容**是不是**什么（题面/公式/答案/结构），与哪条数据对齐 |
| **置信度** | `high` \| `medium` \| `low`（定义见 §3.3） |

建议再加两栏（有则必写）：**对照**（与已入库数据/其它来源的一致性）与**转写不确定项**（有疑则写明疑虑点）。

### 3.2 模板

```markdown
### R<序号> <一句话标题>（<材料简称> p<页码>）
- 材料: 参考文件/.../xxx.pdf
- 页码: PDF p12（册内页脚「· 12 ·」）
- 生成命令:
  python tools/refs-vision.py --pdf "参考文件/.../xxx.pdf" --page 12 --dpi 150 --box <x0,y0,x1,y1>
- 裁片: backup/scratch/refs-vision/<材料>/<PDF名>_p12_<box>_150dpi.png
  （<W>x<H> px, <bytes> B, sha256 <64 位十六进制>）
- 亲读原文: 「<≥20 字的逐字抄录；公式用 $...$ 写出>」
- 结论: <这条是什么；与 <数据/文件:行号> 的关系>
- 置信度: high
- 对照: <与已入库记录/其它来源的一致性；不一致时写差异>
- 转写不确定项: 无 ／ <具体字符/符号的疑虑>
```

### 3.3 置信度三档

| 档 | 判据 |
| --- | --- |
| `high` | 裁片上**逐字清晰无歧义**，且与独立复核/其它来源一致；可直接作为基线 |
| `medium` | 关键内容可读，但有**至少一处**需要判断（模糊字符、OCR 对照、页码需推算）；用时应标注 |
| `low` | 只能读出大意或部分字符；**不得**作为下游入库依据，须换更高 dpi/更小裁片重读 |

### 3.4 与 OCR 文本的配合

- OCR 文本的作用是**定位**（`参考文件/_extract/*.txt` 的 `========== 第 N 页 ==========` 分隔行），不是取证。
- 当 OCR 与裁片冲突时：**以裁片为准**，并在「对照」里写下 OCR 讹字原样（例：`e-smx-1` → `e^{-\sin x}-1`）。
- 若裁片也读不清，写 `置信度: low` + `结论: 未裁定`，**不要**用 OCR 猜测填坑。

### 3.5 目录约定（本波次四族）

| 族 | 基线文件 | 裁定文件 | 备注 |
| --- | --- | --- | --- |
| 统计教材族 | `docs/refs/stats-textbook.md` / `.json` | `docs/refs/rulings/stats.md` | 茆诗松 490 页 + 14 个统计专题 + 计量讲义 45 页 |
| 微观族 | `docs/refs/micro.md` / `.json` | `docs/refs/rulings/micro.md` | 微观十八讲 417 页 + 光华修订版 64 页 + 光华答案册 149 页 |
| 数学三真题族 | `docs/refs/math3-zhenti.md` / `.json` | `docs/refs/rulings/math3-zhenti.md` | 真题 6 份 149 页 + 解析 39 份；2020–2022 段须视觉转写 |

## 4. 示例裁定（完整可复现）

以下是本工具与格式的**活样例**，同时也是数学三真题族的第一条裁定。

### R1 2025 年数学三第 1 题（题干与四个选项）

- **材料**: `参考文件/真题/数学/5、【1987-2025年】考研数学三真题/2025年考研数学三真题.pdf`（扫描册，第 6 页另有答案页）
- **页码**: PDF 第 2 页（册内页脚「2025年考研数学三真题 第 1 页」；本册 PDF 第 1 页是封面）
- **生成命令**:

```powershell
& "参考文件\_venv\Scripts\python.exe" tools\refs-vision.py --pdf "参考文件/真题/数学/5、【1987-2025年】考研数学三真题/2025年考研数学三真题.pdf" --page 2 --dpi 150 --box 55,94,542,220
```

- **裁片**: `backup/scratch/refs-vision/真题__数学__5、【1987-2025年】考研数学三真题__2025年考研数学三真题/2025年考研数学三真题_p2_55_94_542_220_150dpi.png`
  （1014×262 px，35855 B，sha256 `803b55faf9a71fdb1ca6e326b9d54c34d04848e7f62989b8aa7ed80f653e56d7`）
- **亲读原文**（含题号行上方的说明行残句，裁片原始换行照录）：

  > 要求的，请将所选选项前的字母填在答题卡指定位置.
  > (1) 当 x→0⁺ 时，下列无穷小量中，与 x 等价的是（　）
  > (A) $e^{-\sin x}-1$　　(B) $\sqrt{x+1}-\cos x$
  > (C) $1-\cos\sqrt{2x}$　　(D) $1-\dfrac{\ln(1+x)}{x}$

- **结论**: 2025 年数学三第一大题第 1 题的题面与四选项，与 `data/bank_math3.js:237-245` 的 `m3-2025-1` 记录**逐字一致**
  （`stem` 与 `options` 四项均对齐；答案为 **C**，见该记录 `answer`）。
- **置信度**: `high`
- **对照**:
  - 已入库题面：`data/bank_math3.js:241` 的 `options` 四项与本裁定逐字相同；`:240` 的 `stem` 同。
    ⚠️ 落地写法差异（非内容差异）：JS 源文件会把反斜杠转义成 **双反斜杠**（如源文件里是 `$x\\to0^{+}$`、
    `$\\mathrm{e}^{-\\sin x}-1$`），渲染后的实际字符串是单反斜杠；本记录按「渲染后的字符串」写，两边内容等价。
  - OCR 文本 `参考文件/_extract/真题__数学__5、【1987-2025年】考研数学三真题__2025年考研数学三真题.txt` 第 10–12 行同段为碎裂形
    （`e-smx-1`、`√x+1-c0Sx`、`1-Im(1+x）`）——本裁定以裁片为准，裁定该三处为 `e^{-\sin x}-1`、`\cos x`、`\ln(1+x)`。
  - 答案 C 的独立复核：逐项除以 x 求极限——(A) → −1、(B) → 1/2、(C) → 1、(D) → 1/2，仅 (C) 与 x 等价 ✓。
- **转写不确定项**: 无（四个选项的字母、根号、分式与上下标在裁片上均清晰可辨，无一处需要猜测）。

**重建与复核**（任何时候都可执行）：

```powershell
# 重建（应得到同一 sha256）
& "参考文件\_venv\Scripts\python.exe" tools\refs-vision.py --pdf "参考文件/真题/数学/5、【1987-2025年】考研数学三真题/2025年考研数学三真题.pdf" --page 2 --dpi 150 --box 55,94,542,220
# 复核既有裁片（exit 0 = 一致）
& "参考文件\_venv\Scripts\python.exe" tools\refs-vision.py --pdf "参考文件/真题/数学/5、【1987-2025年】考研数学三真题/2025年考研数学三真题.pdf" --page 2 --dpi 150 --box 55,94,542,220 --verify
```

## 5. 已知局限（用之前先看这里）

1. **只做取证，不做识别**：工具只把页面渲染成图，**不**提取文字、不做 OCR、不做公式识别。
   任何「把图变成字」的动作都由裁定者经主通道 `read_image` 完成并负文责。
2. **±1 px 尺寸差**：PyMuPDF 的 `get_pixmap(clip=...)` 在某些页面几何下会给出 ±1 像素的尺寸差
   （如 100 pt × 150/72 = 208.3 px 实得 209 px）。这是渲染边界的取整，**不影响可复现性**（sha256 稳定），
   但裁定记录里的像素尺寸要照实抄自工具输出，不要自己按公式算。
3. **裁片必须目视确认**：工具无法知道 `--box` 是否切掉了内容。每次定稿前用 `read_image` 看一遍，
   确认「题号、题干、全部选项、公式分式」都没有被截断（尤其分式下沿、上下标、矩阵括号）。
4. **旋转页**：`rotation≠0` 的页面按旋转后视觉方向渲染；`--box` 始终以**旋转后所见**的左上角为原点。
5. **跨页内容**：一道题跨页时分别裁两片，**两条裁定**各记一行，不要合成一条。
6. **明文禁止**：不要把裁片提交进仓库（`backup/` 已忽略）；不要在裁定记录里引用 modlens 的结果；
   不要用 OCR 文本充当亲读原文。
7. **写文件编码**：本仓库一律 **UTF-8 无 BOM**；PowerShell 默认编码不是 UTF-8，写文件请用编辑器/专用工具，
   不要用 `>` 重定向生成文档。
